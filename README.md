# حسابي | Hesabi

تطبيق Android احترافي لإدارة المحلات التجارية — **المرحلة الأولى**

تطبيق متكامل يعمل **بدون إنترنت** (Offline-first) مبني بتقنيات Android الحديثة، يدعم اللغة العربية مع اتجاه RTL كامل، ويوفر إدارة المنتجات، المخزون، نقاط البيع، والفواتير.

---

## الميزات المنجزة في هذه المرحلة

| الوحدة | الوصف |
|---|---|
| **إعداد المتجر (Onboarding)** | شاشة إعداد أولية عند أول تشغيل: اسم المتجر، العملة (ريال/دولار/جنيه/درهم/شيكل)، ورمز العملة. يُحفظ الإعداد محليًا ولا يظهر مجددًا. |
| **الصفحة الرئيسية (Dashboard)** | لوحة معلومات: مبيعات اليوم، عدد فواتير اليوم، قيمة المخزون، المنتجات منخفضة المخزون، مع تنقل سريع لكل الأقسام. |
| **إدارة المنتجات** | إضافة/تعديل/حذف المنتجات (حذف آمن Soft Delete). لكل منتج: الاسم، الباركود، الكود الداخلي، سعر الشراء، سعر البيع، الكمية، الحد الأدنى، الوحدة، صورة (التقاط بالكاميرا)، ووصف. البحث والتصفية، والفرز حسب الاسم أو السعر أو الكمية. |
| **المخزون** | حركات المخزون (إضافة، سحب، تجميع، أولية) مع سجل كامل لكل منتج (التاريخ، النوع، الكمية السابقة/الجديدة، الملاحظة). تعديل المخزون الفعلي. |
| **نقاط البيع (POS)** | شاشة بيع: بحث واختيار المنتجات، تعديل الكميات، الخصم، التحقق الآمن من المخزون قبل البيع، الدفع النقدي مع حساب المتبقي، **مسح الباركود** بالكاميرا (ML Kit Barcode Scanning). |
| **الفواتير** | قائمة الفواتير مع الفلترة بالبحث، عرض تفاصيل الفاتورة (المنتجات، الكميات، الأسعار، الخصم، المجموع، طريقة الدفع)، ومشاركة نصية للفاتورة. |
| **التخزين المحلي** | قاعدة بيانات Room (SQLite) — كل البيانات محفوظة محليًا؛ التطبيق يعمل بالكامل بدون إنترنت. |

## البنية التقنية

| المكوّن | التقنية |
|---|---|
| لغة | Kotlin 1.9.x |
| واجهة المستخدم | Jetpack Compose + Material 3 |
| قاعدة البيانات | Room (SQLite) مع Flow للرصد الحي |
| النمط المعماري | MVVM + Clean Architecture (domain / data / ui layers) |
| النقود | تمثيل `Money` بـ `Long` بوحدة العملة الصغرى (هللة/سنت) لتجنب أخطاء التقريب |
| الكاميرا والباركود | CameraX + ML Kit Barcode Scanning |
| الصور | Capturable (تصوير الشاشة) + التقاط صور المنتجات |
| الاختبارات | JUnit 4 + kotlinx-coroutines-test + Turbine (17 اختبارًا للوحدات، كلها ناجحة) |
| الاتجاه | RTL كامل مع خط Tajawal العربي |
| الحد الأدنى | Android 7.0 (API 24) — يستهدف API 34 |

## التثبيت والتشغيل

### من Android Studio

1. افتح المجلد في Android Studio (File → Open).
2. انتظر مزامنة Gradle (ستنزّل التبعيات تلقائيًا).
3. شغّل المشروع على جهاز محاكاة أو هاتف حقيقي.

### من سطر الأوامر

```bash
# نسخ المشروع
git clone <repo-url>
cd hesabi

# بناء النسخة التجريبية
./gradlew assembleDebug

# التشغيل على جهاز متصل
./gradlew installDebug

# تشغيل الاختبارات
./gradlew testDebugUnitTest

# APK في: app/build/outputs/apk/debug/app-debug.apk
```

> ملاحظة: على Linux تأكد من تثبيت JDK 17+ وأن `ANDROID_HOME` يشير إلى Android SDK.

## القرارات التقنية الرئيسية

**الدقة المالية:** جميع المبالغ تُخزن كـ `Long` بوحدة العملة الصغرى (مثال: 15.50 ريال = 1550)، وتُعرض فقط عند العرض النهائي. لا يوجد أي `Float` في المسارات الحسابية.

**سلامة البيع:** إتمام البيع داخل معاملة Room واحدة ذرية: خصم المخزون، تسجيل الحركة، حفظ الفاتورة وعناصرها. أي فشل يؤدي للتراجع الكامل (Rollback) فلا تضيع أموال أو مخزون.

**التحقق من المخزون:** يتم قبل الإضافة للسلة وأثناء إتمام البيع مع رسائل واضحة للمنتج الناقص.

**الحذف الآمن:** حذف المنتج يُخفيه فقط (Soft Delete) فلا يؤثر على الفواتير السابقة المرتبطة به.

**الاختبارية:** منطق الأعمال مفصول عن Android (Pure Kotlin) ومغطى باختبارات وحدات.
